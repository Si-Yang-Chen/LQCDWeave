# 搜索优化竞赛提示词

你参加 本软件 搜索效率优化竞赛。请在独立 checkout 中从发起者给出的统一冻结提交开始，实际修改、测试并提交代码。不要 push，除非我另外明确要求。遵守 AGENTS.md，课题数据和临时报告放仓库外。不要修改评测脚本以获得成绩。

目标：大胆消除或替换可避免的整体开销，提高持续 DFS 搜索吞吐，同时保留全部功能、合法候选、评分语义、确定性规则、预算规则和结果正确性。优先寻找算法级复用与增量更新。不能通过减少问题规模、搜索宽度、ties、根分支数、状态预算，提前停止，跳过必要工作或改变精度取得加速。不要预先硬编码此输入的路线或成本。

统一设置：time_per_term；根宽度恰好4；内部宽度4，include_ties=True；单搜索进程；max_states=1536；deadline=600秒；禁止存储排期。该基准包含首路径之后持续搜索和回溯，首路径加速不能代替持续搜索加速。不得重复 CUDA 探测或开展 GPU 测试。

输入档案路径与 SHA256 由发起者在下方填写。使用 benchmarks/planning_search/run.py，详读同目录 README.md。先测冻结基线，再优化。相同机器、固定CPU核心、BLAS单线程、PYTHONHASHSEED=0；新进程、串行交错至少3次，分别汇报搜索、展开、执行表生成、总规划时间、Linux RSS/HWM。正式计时不插桩；热点逐项计时另开 profile。若deadline先到或展开状态数不同，不是同工作量比较。

用冻结版对照核验：候选/评分/回溯语义、预测成本、DAG和顺序摘要、操作数、输出结构和系数。路线改变时解释原因，并提供独立复数NumPy参考，不能仅比较总成本。运行 planning 全套和 CPU execution 全套（排除cupy），为新行为补必要边界测试；代价模型预测秒数不是真实数值缩并耗时。不要把元数据测试称为完整物理生产验收。

交付：代码提交号、逐项改动及正确性依据、全部测试结果、原始基准JSON路径、三次中位数与加速比、各阶段耗时/内存表、残余热点和限制。目标持续搜索相对统一冻结版至少10倍；达不到也如实报告，不得用其它指标替代。每个通过测试的改动本地提交，所有选手分别使用独立分支与checkout。
