# 完整 cfg 绑定的值身份与成本

cfg 交付将已固定的 Action/存储计划绑定到真实坐标，分配全局值 ID、共享关系、最后使用位置、
读块事件和内存包络。这里只处理元数据，不展开算符、不搜索路径、不读取数值数组。

## 原生 whole baryon 的值身份

原生 `Action(kind='baryon_join')` 搭配原生 `TensorCoreSpec(kind='baryon')` 时，
`term_index` / `positions` / `join_id` 是固定计划的证明位置或名称。相同的有序实际输入及完整内核声明产生同一个值，
不应因证明位置不同而覆盖共享的本地输出名，造成孤立的释放 ID。

身份继续包含有序实际端点、完整 core 身份（有序分量、系数、稀疏自旋、形状、精度和具名轴）、
规范化方程/有序输出轴、路径、稀疏和布局参数、资源/精度选项及 `kernel_description`。
方程规范化只重命名 dummy 轴，保留自迹/对角轴的等同关系及输出轴顺序。
`core.inputs` 中的逻辑输入名仍保留，不能据此泛化为任意重命名的 core 等价。
原生有序 join（`core=None`，即 `baryon_vertices="joined"` 的稀疏自旋专核/有序 join）同样只由
有序端点、方程、稀疏自旋与路径定义值，执行器不读取 `term_index` / `positions`，因此走同一身份规则。
扩展 Action/core、`sparse_bridge` 等其它特殊操作仍走原来的保守身份路径。
默认模式的本地共享证明和 debug 的逐 Action 绑定使用同一个值身份。

值相等不表示必须共用同一块物理所有者。原生 whole baryon 的 cfg 分配另以 P 已选输出名划分
物理所有者，保留其接受预算时的生命周期。相同 P 输出的证明 occurrence 及兼容坐标仍可复用；
不同 P 输出即使绑定后发现实际输入相同，也不在 C 中额外合并成跨很长区间的永久缓存。
原始读块和 preparation 仍按真实输入身份复用，没有增加前端参数或改变 P 动作、顺序、批次与预算。
代价是放弃这部分未在 P 存储包络中选定的跨输出缓存，可能保留更多计算；这与科学值身份分开。

被复用的操作只读取已有结果，不再次读取原操作数。C 的最后使用表及独立 audit 均按实际付费操作
更新操作数/借用原始块的存活期；复用结果自身仍存活至其真实使用位置。窗口结束后需要的相同值
获得新所有者并重新计算，不能把已经释放的物理值当作历史缓存。
