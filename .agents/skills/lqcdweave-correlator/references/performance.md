# 预测、测量与成本模型

新 CUDA 计划默认在已选路线内按成本/完整预算扩大 thin-wide tile，冷编译和暖执行
仍分开记录。仅需关闭这项规划后处理作对照时，用高级
`calculate(..., factorized_retile=False)`；默认 None 对新计划启用。
完整档案保存实际宽度，`plan_archive` 仅接受该选项的缺省 None，显式 True/False
均拒绝，不能在执行时改宽。扩大 partial 的内存代价、一次准备和每 cfg 的
启动/暖链分别外推，不用各阶段加速倍数相乘。规划/归档细节见[规划参考](planning.md)。

重子整体顶点的降阶用高级 `calculate(..., baryon_vertices=...)` 选择：默认 `"auto"` 分别规划按族规则
（拆分能压缩非零元时用两部分拆分，否则用全部非零元）与统一的 `pair`、`nonzero`，保留 CostProfile 预测耗时最小者
（规划时间约为单一形式的三倍，计划档案只做一次）；对照时可强制 `"pair"`（任何秩都拆）、`"nonzero"`、
`"dense"`（整块常量）或 `"joined"`（不打开内核，仅此时不打开）；只影响新计划，`plan_archive` 回放保持档案所选；引入该开关前保存的档案（含介子、胶球）不再读取，需重新规划保存。
各取值的适用范围与对照数据见[重子行打包因子网络](../../../../docs/modules/expansion/baryon-factor-network.md)。

`calculate(..., measure=True)` 或当前固定绑定的 `planned.run(measure=True)` 提供实际报告；
planning_seconds 是规划时间，prediction 是模型预测，report 才包含该路线的测量。
完整窗口执行不接受 measure=True，使用其已有阶段报告，不向任意入口强塞同一参数。

## 精度、目标与计时

- calculate/ContractionTask 在声明时用 dtype 固定输入和输出类型，各数据块先转换再准备。
  省略 dtype 的旧调用按完整输入最低浮点分量精度统一并保留复数，例如 complex64 与
  complex128 混合时采用 complex64。转换进入准备配方和预算。不能临时换 dtype 后复用旧计划。
  单坐标与原生 dense 时间扫描遵守同一规则，自动批宽或末批不足不改变计算精度；
  复系数和 gamma 矩阵不会把 complex64 任务提升到 complex128。用法见
  [完整 cfg 输出与 GPU 后处理](../../../../docs/modules/results/gpu_output_postprocessing.md)。
- 支持 float32/64、complex64/128，整数索引不参与选择；不可描述的混合精度输入明确拒绝。
- target_hardware 决定规划目标，backend 决定执行实现；显式 profile 优先于目标档案模型。
  默认回退模型未校准，不称作目标实测。
- 同设备、同输入、同精度、同坐标覆盖比较结果与耗时。区分冷初始化、准备、IO、传输、
  固定绑定、数值、输出及清理；嵌套或重叠阶段不直接相加。
- 调用数、命中率、预测成本不能代替 wall time、利用率或实测峰值。设备池 used/reserved、
  pool 外分配和逻辑字节分别报告；CPU/协议替身不证明 CUDA/HIP 编译或设备加速。

固定 CUDA spin/profile 准备会自动共享完全相同布局与算术描述的叶子源码，
减少宽 stack 的重复编译工作；当前数值、逐级舍入和输出仍独立，不需要脚本开关。
首次编译成本和稳态收益须分别测量，源码大小不是完整任务耗时的替代指标。

默认 structured dense 介子联合展开可按实际 spin 常量的精确 monomial 支持自动保留
四个非零 spin×spatial 块，并用原整数缩并与 batch GEMM 执行。无需新用户选项；
profile、dagger、PC 和精度契约保持。分组、传播子 spin gather 和布局打包也有成本，
不适用结构保留原 dense 路线；须分别测量首次和稳态，不能只据四倍运算量减少推断提速。

同一次矩阵绑定会自动复用已描述的实际 component/mode 的 spin 支持和已核验的传播子端点，
减少联合任务展开时重复构造元数据。新 cfg/坐标绑定仍重新核验，用户无需添加 loader、缓存或开关。

实际非零 spin 常量为 `±1/±i` 时还可自动共享纯空间准备和传播子乘积，保留显式小
spin 因子；profile 舍入与模式/坐标身份必须相同。窄精度的最后空间与 spin 求和
由存档数值约束保留宽累加，不先落窄 Gram。仍需核实公共 P 实际选中的共享 producer，
并计入小 spin 组合的额外数据；手写 Gram 原型不能代表默认入口收益。

复杂空间投影的单位相位路线自动保留唯一空间 component 轴，每个实际端点/有序模态
job 一个 Term；小系数包保留每个投影贡献槽，不预先窄求和。mode、spin、component
与贡献槽由同一个宽求和边界关闭，P 可以直接选择有界分块的三/四输入宽归约。
固定档案保存已选 tile、布局和资源安排，执行不重规划。无需用户添加选项或手工分组。
并行 worker 的终端宽归约仍由 owner 独立核对操作数角色、轴关系与声明的输出顺序，
不把串行快路通过当作进程交接已经通过。
Term 数减少不代表数值运算或显存同时减少；验证完整公共单点/有限窗口的准备、
首次/暖机耗时、实测峰值及独立 c128 原阈值，再判断是否采用。

输入准备、执行表、输出队列与内部代码生成优化的细节见
[执行 L2](../../../../docs/modules/execution/execution.md)和[性能 L2](../../../../docs/modules/performance/performance.md)。
评估实现修改时按真实影响选必要的独立参考与生命周期检查，不把历史每项微优化都变成常规流程。

## factorized_gram_strategy

`calculate(..., factorized_gram_strategy=...)` 提供一个策略入口：`'reduction'` 保留原实现，
`'tiled'` 复用相邻输出点的大输入读取，`'gemm'` 在新离线准备中尝试显式预算的全宽 Gram。
默认 None 对新 CUDA 任务启用上述保守候选，对其它新任务等于 reduction，对档案跟随已保存的数值策略。常规调用无需设置。
GEMM 只作用于 P 证明适用且成本/内存准入的四输入矩阵；splitK、retained lanes、其它
small 轴关系保留归约，并尝试已有 tiled 输入复用；只有 P 实际选中 GEMM 才增加对应已准入 wide 分区，显式 reduction 不增加该预算。X 不缓存数值，
也不能把旧档案临时升级成未预算的 GEMM。浮点累计顺序可以不同，必须沿原 c128 门槛验证。
当前 V100 有界证据只支持大工作量、高输出并行度域；P 另按输出点、逻辑复数乘积数和
每打包字节的逻辑乘积数作保守筛选（阈值见执行 L2），不是普遍校准成本模型。
完整公开 full15 模块在计入额外 P 后支持长链默认选择；短生命周期或需要原实现时显式
设置 reduction/tiled。首次共享缓存触发不能冒称独立冷启动，按实际每 cfg 进程与缓存
策略分别计成本，不把局部速度相乘外推完整生产任务。
实测小输出公共任务没有 GEMM 收益，不能把大域模块收益外推到该任务；即使未选中也
须记录候选筛选的额外 P 时间。

宽 GEMM 的总成本包含两个输入的实际轴重排/complex128 转换、矩阵乘法、完整宽收尾，
不能仅计库 GEMM 时间。两个 small 的轴可能分别跨大输入两侧，形状不能证明双线性投影
可分离；即使可通过 Gram 重排完成，重排和额外小 GEMM 也可能更慢。按完整边界实测选择。

### 兼容参数 factorized_gram_tiling

旧 `factorized_gram_tiling=True/False` 分别兼容策略 tiled/reduction，不与冲突枚举混用。
普通已选对象后续 `.run()` 保持该选择；完整 cfg 档案的
`calculate(plan_archive=..., configuration=tasks, factorized_gram_tiling=True, ...)`
也支持单 cfg 和 iterator。它只影响当前执行绑定，不写入科学档案，不改变已选 tile、
partial 布局、finish、工作区或宽精度累计次序；不适用结构继续通用核。

此选项可能增加首次编译时间，应按实际重复次数比较总耗时。2026-10-21 单 V100
有界 Ne120、生产4/5模态分组、完整7味道/C矩阵与复杂3算符公共入口中，独立新进程和
独立空 CuPy cache 的 first wall 为26.695→30.046秒；8次 warm 的中位为
0.545878→0.529479秒，均值0.582217→0.547051秒（两组均含尖峰）。first 包含编译和
当前输入准备，不能全部归因于 NVRTC。原独立 c128 门槛全部通过；这不是完整273任务验收。

该模块中首次额外3.351秒约需205个 warm 点回收（用均值则96个，尖峰影响较大）。
假设每个源汇点重复同一模块成本，40源×40汇×20cfg，共32000点；若每cfg一个新进程
且各自空 cache，模型为 `20*first + 31980*warm`，中位模型17991.1→17533.7秒，
均值模型19153.2→18095.6秒。若一个进程运行全部cfg且只支付一次 cold，则
`first + 31999*warm`，中位17494.2→16972.8秒。每个点都启动独立空 cache 进程反而更慢。
新进程共享已有磁盘 cache 的加载成本未在这次测量，不能直接当作 warm。
不把此模块比例乘以其它优化比例，也不据此宣称完整任务收益成立；完整任务确认前保持默认关闭。

## 联合任务的性能核验

完整兼容测量联合选路后，比较共同准备、读取/绑定、窗口排程、回放和发布；
核对所有通道及坐标。单通道微测不替代完整工作量。

普通坐标排程复用批内相同轴模式及已命名的中间量；单批沿用该批已完成的存储审计，
多批仍核对跨批生命周期。这减少主机端描述构造，不表示 GPU 数值计算已加速；
固定回放与包含坐标排程的调用仍分别计时。

原生 CuPy 同 batch extents/dtype 的批矩阵可省去重复的 GUFunc 参数处理，仍调用原来的数值例程；
原例程处理连续及步幅视图，batch 广播、精度或入口包装不满足条件时保持公开路径。该后端优化无需新增用户参数，
其收益须以完整任务墙钟和 GPU 利用率分别验证。

默认数值模式下，float64/complex128 的长批内积（每个矩阵输出为 1×1，
归约长度至少 4096）复用两阶段双精度归约，输入、乘积、累加和输出均不降精度，
临时量受原 Action 的输入加输出工作区约束；其它矩阵仍用原入口。
这不是跨 Action 的 `kernel_batching`。debug、非默认计算/math 模式、入口包装或
能力缺失时保留原矩阵路线。归约顺序可能改变，必须沿用任务原定误差标准对照，
微测收益不能代替完整关联函数的数值和耗时验收。

## kernel_batching

CUDA终端标量归约在新规划中按参数与内存预算选择最多32个独立成员，
内部源码容量为8/16/32；高rank自动保留较小容量，Cartesian矩阵分组仍最多8个。
旧档案按已保存分组回放，不因升级自动扩宽；每成员宽精度求和树和dtype不变。
这只减少提交次数的上界，仍须同任务核验数值、冷暖耗时和内存，不能由CPU协议计时推断GPU提速。

内存内 `.run(time_axes/time_pairs=..., batch=...)` 沿用原 `kernel_batching` 选择，
按已登记目标统一考虑适用的独立 GEMM、scalar 和 Cartesian 归约分组。动态时间批轴
保持原代数含义，几何不支持的操作继续原路。未知 runtime 不自动视为 CUDA；不增加
用户开关，也不需要在脚本中再次合批。分组与共享输入的预算检查均在读取前完成，
统计中的分组数和理论提交减少不代表完整任务已提速。

`kernel_batching=False` 为默认。`True` 允许后端在新规划中把兼容、独立的缩并合成
较大的物理内核；能否应用取决于依赖、布局、成本模型和资源预算，不保证每项都合批。
它与时间坐标的 `batch` 参数独立，不改变物理算符、坐标覆盖或估计量。
关闭时仍联合规划并复用共享中间结果，只跳过普通 Cartesian 合批以及 CUDA 的独立 GEMM、
终端标量归约分组；
开启也不意味着每个批都会使用 GEMM，窄精度归约仍须遵守下述宽精度规则。

该开关的设备范围如下；具体操作仍须满足已选计划的准入条件：

| 执行方式 | CPU | CUDA GPU |
|---|---|---|
| 普通 Cartesian 内核合批 | 开启时可用 | 开启时可用 |
| 独立 GEMM、终端标量和 Cartesian 宽精度归约分组 | 不启用这些 CUDA 专用分组 | 开启时按支持的几何使用 |
| 公共执行表、适用的绑定缓存与静态审计复用 | 不受合批开关控制 | 不受合批开关控制 |

因此，关闭合批不是退回每次重新规划或重建全部执行结构。开启合批也不等于并行执行
多个时间对：时间坐标 `batch` 和窗口安排仍由各自入口及预算决定。CPU/debug 的参考路线
与原生 CUDA 核不同，不能沿用 GPU 的提速结论。

在完整任务的首次联合规划中显式选择，随后复用该计划：

```python
calculation = calculate(
    correlator, propagator_map=propagators, vertex_map=vertices,
    execute=False, kernel_batching=True,
)
result = calculation.run()
```

已有档案沿用保存的合批选择；切换该选项需重新规划，不能给档案加载或 `.run()`
临时添加合批覆盖，见[计划档案](plans.md#联合任务与一次规划反复回放)。

### 重复回放的复用边界

公共执行路径复用已绑定的执行表、已编译的内核及有界的布局/调用参数缓存。
CUDA 终端标量归约组按固定成员分别保存布局缓存，共享兼容的内核源码，避免不同组
因几何相同而挤掉彼此的步长组合。布局命中可省去重复构建调用参数，但每次仍核对
当前数组的 shape、dtype、步长及设备，并更新当前指针；这不缓存传播子或 elemental 数值。
更换时间对或 cfg 后，不得因为执行表命中而跳过读取和必要的数据准备。

完整 cfg 回放还可在同一兼容计划内复用一个有容量上限的节点键表，适用于 CPU/GPU。
它只保存键；每个时间对仍建立独立的当前节点 ID 绑定，不保留历史数组、reader 或地址。
这些公共复用不依赖 `kernel_batching=True`，不能把它们的收益都归于合批。

普通 `.run()` 的固定存储回放还可在同一绑定 owner 内复用已成功的静态资源审计。
首次执行仍完整审计并证明描述不可变；debug、可变或扩展描述、临时资源移动保留原审计。
更换计划、预算生成的新计划或后端会重新审计；当前输入、loader、设备及动态预算检查
仍每次执行。这项复用适用于 CPU/GPU 共用的普通回放，完整 cfg 热执行原本已不重复
进行该深度审计，不能把这部分节省外推成完整 cfg 的加速。

因此稳定期可省去部分绑定和参数构建，首次编译、未命中布局的绑定，以及该次确需的
打包、上传和数值计算仍会发生。缓存有容量限制，不能承诺每次都命中，也不能从缩并
内核计时推算整个 `.run()` 的耗时；定位收益时分别计时准备、绑定、打包/传输与执行。

下列实现优化由公共执行路径管理，用户不必在脚本中另建缓存或操作共享缓冲：

| 优化 | 适用范围 | 复用或节省的内容，以及必须保留的操作 |
|---|---|---|
| 固定执行表、静态审计与有界节点键表复用 | CPU/GPU，按上述入口边界 | 复用结构与已证明不可变的描述；当前数据绑定、必要准备和动态资源准入仍执行 |
| 归约调用参数与内核源码复用 | 支持的原生 CUDA 归约 | 复用代码和布局参数；每次核对当前数组元数据并更新地址，首次或新布局仍需绑定 |
| 小归约结果共用分配块 | 满足逐 owner 预算证明的普通 dense CUDA 组 | 减少分配与视图构造；每次仍生成新结果，共享块到最后一个结果释放才回收 |
| 合并输入打包及原始输出复制提交 | 支持的 CUDA 分组/下载路径 | 减少提交次数；所需复制字节、所有权和预算仍按实际流程核算，不能推断传输已经消失 |

减少分配、提交次数或 Python 操作只能说明局部工作减少；GPU 利用率和完整任务耗时
仍可能没有改善。具体任务的收益以实际对照为准，不把某个微测或单次结果写成通用保证。

### 代价与使用判断

| 代价或副作用 | 使用时如何判断 |
|---|---|
| 额外规划、绑定和首次 GPU 编译 | 分别报告首次完整执行与后续回放，启动成本也计入实际任务的累计耗时 |
| 输入打包、复制和布局重排 | 减少提交次数可能增加访存；不能只看 GPU 利用率或合批次数判断加速 |
| 更大的共享缓冲和更晚的释放 | 整批输入打包及结果所有权由计划计费；共享结果缓冲到最后一个使用者结束才释放，整体峰值可能增加 |
| 浮点舍入变化 | 输入/输出 dtype 保持计划约定；内核及求和顺序可能变化，按任务原定标准核对。要求逐位一致时，差异仍算未通过；采用误差容限时，须有独立参考与已确定的绝对/相对误差界，不能临时放宽 |
| CPU/debug 或其它回退路线变慢 | 小工作区的宽精度参考可能逐输出、逐元素求和，GPU 收益不能外推到 CPU 或回退路径 |

合批改变的是物理执行方式，不能借此省去当前输入的 shape/dtype/布局检查、设备与上下文
确认或资源预算准入；执行表和代码复用不等于复用上次的传播子、elemental 或设备指针。
跨坐标或通道共享中间结果时，还必须匹配保存的生产者输出布局；数值相等不证明能直接
借给 prepared side。布局不符应修复规划或生产者交接，不能删掉检查或临时补拷贝绕过预算。
实例因部分结果复用而跳过合批时，仍须保留模板声明的生产者布局，供后续固定回放借用。
这也可能推迟该批其他结果的生产时刻。P 必须按实例中实际输入的可用时刻检查下游合批：
过早的 GEMM 组保留原子批的保存位置，仍过早的原子批保留原 Action；同步核算工作区。
该安排在 cfg 绑定时冻结，X 不得在取数失败后补搜路径、重排或临时回退。

含虚拟自由轴的 float32/complex64 归约批仍保留宽精度累加，额外归约临时量受原成员
工作区约束；这不免除整批打包和共享输出的独立计费，不能把窄精度 GEMM 当作等价替代。
CUDA 终端标量分组只合并已有宽精度内核资格、几何相同且输入已驻留的独立归约，
需要额外计入同时存在的 partial 和提前生成的结果。支持的普通 dense CUDA 归约组，
小结果可共用一个分配块，每项仍是互不重叠的视图；共享块保留到最后一个结果释放。
仅在整组输出不超过一个最小分配单元、且生命周期预算证明成立时采用；其它情况
保留独立分配。减少分配和视图构造不改变归约步骤或累加精度，也不复用上次结果的值。
兼容的 CUDA Cartesian 归约组可合并同侧输入打包，每次提交最多32个源，较宽侧分块
写入同一缓冲；保留原内维次序、当前输入检查和预算，prepared 侧继续借用生产者输出。
减少提交可能牺牲原子批的单独零复制借用，仍须用包含打包的完整回放判断收益。
cfg 实例仅复用部分成员时整组退回原位置逐项计算，不在 `.run()` 中重新选组。
该分组的成本暂沿用原成员之和，预测值不能证明实测加速。
优先在存在大量兼容小缩并、需要重复回放且实际累计耗时降低时采用；单次或少量执行
保留默认，除非已有同设备、同输入的证据支持开启。比较应使用相同任务、精度和计时
边界，同时看首次成本、稳定期总耗时、数值误差与资源峰值；成本模型预测和 GPU 活动率
不能代替端到端收益。具体课题的成绩与阈值按[项目材料约定](../../../../AGENTS.md)留在项目目录，不写成通用默认。

默认 CUDA 规划还可把已选整数因子图中的两项展开乘法与其宽精度终端归约，
合成一个显式四输入 `FactorizedWideReduction` Action。只有实际 `sum_barriers`
声明要求在此闭合宽求和、两个展开结果各仅供该终端使用，且小 Gram 的完整工作区
与成本均通过准入时采用。空间乘积和准备阶段保留既有 dtype/舍入；Gram partial
仅是内部 complex128 工作区，小因子组合继续宽累加，最终输出才转回 complex64。
不把窄 Gram 再组合当作等价路线。该 Action 和几何随固定档案保存，X 不重选图；
旧档案、其它 dtype、稀疏连接或不支持的因子几何保留已选普通路径。
PC/径向投影的实际有序 mode job 若满足同一因子几何，也由普通候选服务准入；
投影本身仍沿原输出配方执行。
已选薄归约也支持 `.run(time_pairs=..., batch=...)` 的固定坐标提升：保留的 lane
进入显式几何与工作区，不重新展开 Gamma，也不跨坐标混加内部 Gram。

固定矩阵联合展开会在本次绑定内复用实际成分/有序模态选择的单位相位判断，
并按已登记输入身份复用完整空间准备描述；无需额外选项。该复用不跨 cfg 保存
数据，不改变 profile 舍入、源端 dagger、精度边界或输出配方。复杂通道仍可能有
大量真实空间分量组合；局部 CPU 描述加速不代表 GPU 或完整生产任务的加速。
